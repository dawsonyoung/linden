## Problem

A user who wants AI assistance today must send their questions to a remote service. There is no way to verify what is retained or reused, and the assistant stops working without internet access.

## Users and jobs

Privacy-conscious individuals who want to ask questions, draft text, and reason through problems without their input leaving the device.

## Scope

- Send a message and receive a reply generated by a locally running model.
- See the reply stream in as it is generated rather than waiting for completion.
- Stop a reply while it is generating.
- Choose which locally available model answers.
- Retry the last message.

## Non-goals

- Retrieval over personal documents. Separate PRD.
- Multi-device access. Separate PRD.
- Conversation history that survives a restart. Separate PRD.
- Any remote model provider.

## Requirements

1. R1 — A message sent from the client returns a reply generated entirely on the local machine.
2. R2 — Reply text appears incrementally while generating.
3. R3 — The user can stop generation and keep the partial reply.
4. R4 — When no local model is available, the user sees an actionable message naming what to install.
5. R5 — When the local model backend is unreachable, the user sees an actionable message and the client remains usable.
6. R6 — The user can select from the models available locally.

## Privacy considerations

Message content is sent to the local model backend and held in memory for the duration of the request. Nothing is written to disk in this capability, and nothing leaves the device. Message content never appears in logs at any level.

## Success criteria

- A first-time user can install, start Linden, and receive a reply without editing a config file.
- Disconnecting from the network does not change behavior.
