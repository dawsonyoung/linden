# Linden LLM Context

This file provides a high-level orientation for LLMs working in this codebase.
For full agent instructions, see AGENTS.md.

## What This Project Is
Linden is a privacy-first, safety optimized personal AI platform featuring streamlined deployment of the local-only chat experience. All inference runs locally via Ollama.
No user data leaves the device by default.

## Repository Layout
- src/          — Go server (cmd, api, orchestrator, inference, storage, discovery, mcp) + SvelteKit web
- validation/   — contracts, integration, security, smoke test suites
- prompts/      — reusable prompt templates for product and dev use
- evals/        — AI output evaluation datasets and test harnesses
- tools/        — MCP-compatible tool definitions and sandboxed plugins
- .agents/      — agent workflow definitions and role configurations
- .mcp/         — MCP server configuration and tool manifests
- .context/     — orientation index for agents; points at sources, never duplicates them
- docs/product/  — published product spec and PRDs (what Linden does, for humans)
- docs/architecture/ — layer interfaces and dependency rules
- docs/project/  — branching, contract-first delivery, agent workflow
- docs/adr/      — architecture decision records
- plans/         — holding area for forward-looking designs, architecture proposals, and candidate implementation plans

## Key Rules for AI Agents
- Consult `plans/` for forward-looking design guidance or when tasked with specific future plans.
- Never log user data, not even at debug level.
- Validate all input at the API boundary (src/api).
- Layers communicate only through their defined interfaces; no layer reaches into another's internals.
- Do not add features, abstractions, or comments beyond what was explicitly requested.
- When uncertain, add a TODO comment rather than guessing at design intent.
- This is a privacy product. Every line of code should be audit-ready.
